# 开发规范

## 1. 分支模型

| 分支 | 命名 | 用途 | 合并方向 |
| --- | --- | --- | --- |
| 主分支 | `main` | 可运行、可提交版本 | `develop` → `main` |
| 集成分支 | `develop` | 每周集成 | `feature/*` → `develop` |
| 功能分支 | `feature/home`、`feature/cart`、`feature/login` | 单模块开发 | → `develop` |
| 修复分支 | `fix/cart-total` | 缺陷修复 | → `develop` |
| 文档分支 | `docs/submit` | 文档、素材 | → `develop` |

规则：

1. 不直接在 `main` 上提交；`main` 只接受评审通过的 PR。
2. 每个功能分支只做一件事，生命周期不超过 3 天。
3. 合并前先 `git pull --rebase origin develop`，本地运行通过后再提 PR。
4. 合并后删除远端功能分支。

## 2. 提交信息

格式：`类型(模块): 简述`

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| `feat` | 新功能 | `feat(home): 完成商品列表懒加载` |
| `fix` | 修复缺陷 | `fix(cart): 修正合计金额计算` |
| `docs` | 文档 | `docs: 补充测试用例` |
| `style` | 样式/格式 | `style(profile): 统一卡片圆角` |
| `refactor` | 重构 | `refactor(service): 抽取订单快照` |
| `chore` | 构建/配置 | `chore: 初始化工程` |

一次提交只做一件事；不要提交 `build/`、`oh_modules/`、签名文件。

## 3. ArkTS 编码约定

1. **显式类型**：变量、参数、返回值尽量写类型；禁止 `any`。
2. **对象字面量必须有类型**：优先使用 `interface`，路由参数使用 `class`。
3. **页面只做展示**：数据读写放到 `service/`，页面通过 `@StorageLink` 响应变化。
4. **服务使用静态方法**：`XxxService.xxx()`，不持有页面状态。
5. **常量集中**：路由、存储 key、分页大小放 `common/constants/`；颜色、圆角放 `AppTheme`。
6. **组件复用**：商品卡、空状态、页面导航栏已抽取，禁止复制三份。
7. **注释**：公共类、复杂计算、Mock 边界必须写中文注释；页面顶部写职责说明。
8. **资源命名**：`ic_` 图标、`product_` 商品图、`banner_` 轮播图，全部小写下划线。

## 4. 共享文件 ownership

以下文件由组长维护，修改前必须在群里说明，避免冲突：

| 文件 | 原因 |
| --- | --- |
| `model/Product.ets` | 全组共享的数据结构 |
| `model/CartItem.ets` | 购物车与页面共享 |
| `model/Order.ets` | 订单与个人中心共享 |
| `common/constants/RouteConstants.ets` | 所有页面路由 |
| `common/constants/AppConstants.ets` | 存储 key 与全局常量 |
| `common/theme/AppTheme.ets` | 全组视觉规范 |
| `entry/src/main/resources/base/profile/main_pages.json` | 页面注册，改动会影响全部路由 |
| `build-profile.json5` | 构建版本，需全组统一 |

## 5. PR 流程

1. 从最新 `develop` 切出 `feature/xxx`。
2. 开发、自测，提交前执行一次完整主流程走查。
3. 推送分支，创建 PR，标题与提交信息一致。
4. PR 描述填写：变更内容、测试方式、截图/录屏、关联 Issue。
5. 至少 1 人 Review（组长或模块交叉负责人），通过后 squash merge。
6. 合并后删除分支，回到 `develop` 继续下一个任务。

### Review 检查表

- [ ] 页面在手机尺寸下不溢出、不遮挡。
- [ ] 空数据、加载中、失败状态有处理。
- [ ] 金额、数量计算正确，未登录有拦截。
- [ ] 没有硬编码路由、颜色、存储 key。
- [ ] 没有提交构建产物、签名文件、个人配置。
- [ ] 新增页面已加入 `main_pages.json`。
- [ ] 新增资源文件名小写，引用路径正确。

## 6. 冲突处理

- 共享文件冲突：由组长与改动方一起解决，禁止 `--force` 覆盖。
- 页面文件冲突：保留双方功能，先合并逻辑再调样式。
- 资源冲突：重命名后重新引用，避免同名不同图。
- 解决后必须重新编译并在真机走查，不能只看代码。
